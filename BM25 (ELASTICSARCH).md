
BM25 (best match) - алгоритм ранжирования использующийся для поиска текстовых документов по текстовому запросу используя лексическую близость.
$$
\text{BM25}(d, q) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{f(t, d) \cdot (k_1 + 1)}{f(t, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}}\right)}
$$

$d$ — документ.
$q$ — поисковый запрос.
$t$ — термин из запроса.
$f(t, d)$ — частота термина $t$ в документе $d$.
$|d|$ — длина документа (количество слов).
$\text{avgdl}$ — средняя длина документа в коллекции.
$N$ — общее количество документов в коллекции.
$n_t$ — количество документов, содержащих термин $t$.
$\text{IDF}(t)$ — обратная частота документа:
$$
\text{IDF}(t) = \log\left( \frac{N - n_t + 0.5}{n_t + 0.5} + 1 \right)
$$

$k_1$ — коэффициент сглаживания частоты термина ($k_1 > 0$).
$b$ — параметр нормализации по длине документа ($0 \leq b \leq 1$).	

Идея проста - обычный TF-IDF для для вычисления важности токена в документе, основываясь на частоте токена в документе * log(вероятность получить токен в документе коллекции ^ - 1) с поправкой на штрафф лишающий длинные документы преимущества.

Очевидно что мы можем рассчитатать скор для каждого документа и термина на этапе индексации и сохранить.
Мы сохраняем словарь с токенами и для каждого термина мы сохраняем список документов с их скорами для этого термина.

На этапе поиска мы разделяем запрос на термины, и для каждого токена получаем из словаря все документы и их скоры, складываем скоры для повторяющихся документов, по итоговому скору ранжируем документы и возвращаем.

Если есть огромное количество документов в коллекции, то и на этапе поиска нужно будет перебрать очень много документов и посчтитать для них скор, чтобы не считать скор для всех использует [Weak AND](https://docs.vespa.ai/en/using-wand-with-vespa.html) для начального подбора нескольких десятков тысяч кандидатов.
