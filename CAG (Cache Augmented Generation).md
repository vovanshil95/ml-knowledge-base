
Часто происходит ситуация, когда одно и то же начало промпта с разными продолжениями приходит на вход в большую языковую модель, например это может быть единый системный prompt с разными данными идущими после него, также это может быть история чата, начало которая остаётся неизменным, но в которую просто добавляются новые сообщения.

Мы можем сохранять Key и Value матрицы каждого слоя внимания для этого неизменяющегося начала промпта чтобы не считать эти матрицы заново при каждом запросе. Мы можем так сделать потому что знаем, что эти матрицы не будут изменяться при разных запросах, ведь начало запроса остаётся неизменным, а последующая часть запроса, которая меняется от запроса к запросу не будет влиять на Key и Value матрицы начала запроса, тк в LLM контекст из конца промпта не влияет на эмбеддинги начала промпта. Мы сохраняем именно Key и Value матрицы потому что только эти матрицы нужны для получения контекста из начала промпта.

Иногда можно использовать CAG вместо [[RAG (Retrieval-Augmented Generation) идея|RAG]]. Если наша база знаний полностью помещается в окно контекста LLM мы можем просто положить всю базу в начало промпта и сохранить для неё Key и Value матрицы, затем использовать их для каждого ответа LLM, таким образом модель будет иметь контекст из всей базы знаний, как будто она была подана в промпт, но отвечать почти так же быстро как если бы база знаний в промте не было.
