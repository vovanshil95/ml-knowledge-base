

- Какие есть join
	    - INNER JOIN
	      Возвращает только те строки, где есть совпадение в обеих таблицах
	    - LEFT JOIN
	      Возвращает все строки из левой таблицы (TableA) и соответствующие строки из правой таблицы (TableB). Если соответствия нет, для правой таблицы возвращаются NULL
	    - RIGHT JOIN
	      Возвращает все строки из правой таблицы (TableB) и соответствующие строки из левой таблицы (TableA). Если соответствия нет, для левой таблицы возвращаются NULL
	    - FULL JOIN
	      Возвращает все строки из обеих таблиц. Если для строки нет соответствия в другой таблице, недостающие значения заполняются NULL
	    - CROSS JOIN
	      Возвращает все возможные комбинации строк из обеих таблиц (Декартово произведение)


- оптимизация join операций
		- Nested Loops Join
		  Внешний цикл проходит по строкам первой таблицы (outer table)
		  Для каждой строки внешнего цикла внутренний цикл ищет совпадения во второй таблице (inner table)
		  Оптимален, когда одна из таблиц маленькая или есть индексы для быстрого поиска
		- Hash Join
		  Создает хеш-таблицу из меньшей таблицы (обычно по ключу соединения)
		  проходит по большей таблице и ищет совпадения в хеш-таблице
		  Требует достаточно памяти для хранения хеш-таблицы
		- Merge Join
		  Сначала сортирует обе таблицы по ключу соединения
		  Затем проходит по обеим таблицам параллельно, как при слиянии в mergesort
		  Эффективен, когда данные уже отсортированы
		- Grace Hash Join
		  Улучшенная версия hash join для случаев, когда данные не помещаются в память
		  Разбивает обе таблицы на партиции по хешу ключа соединения
		  Затем выполняет hash join для каждой партиции отдельно
		- Hybrid Hash Join
		  Комбинация обычного hash join и grace hash join
		  Часть данных обрабатывается в памяти, остальное - с записью на диск


- Оконные функции
        ```sql
        SELECT
            product_name,
            sale_date,
            sale_amount,
            SUM(sale_amount) OVER(PARTITION BY product_name) AS total_sales,
            AVG(sale_amount) OVER(PARTITION BY product_name) AS average_sales
        FROM sales
        ORDER BY product_name, sale_date;
        
        ```

- parquet особенности хранения
	    Формат **Parquet** (созданный Apache) — это колоночно-ориентированное хранилище данных, оптимизированное для аналитических нагрузок (OLAP). Его ключевые особенности:
		 1. Данные хопняться по столбцам а не по строкам тоетсь если в csv можно быстро взять первые 20 строк не читая весь файл, а только его начало, то в parquet можно быстро взять несколько столбцов не читая весь файл
		 2. Сжатие данных, например алгоритмы RLE (Run-Length Encoding) для повторяющихся значений, Dictionary Encoding для строковых данных, Delta Encoding для временных рядов. Это может снизить расход на память в 4 раза.
		 3. данные деляться на Row Groups, затем row Group делится на Column Chunks, для каждого Column Chunk ищутся статистики например (min/max, null-значения). Например у нас есть таблица 10 000 000 строк на 20 столбцов, и например мы установили размер одной Row Group 1 000 000, тогда у нас будет 10 Row Groups, в каждой по 20 Column Chunks (тк 20 колонок), и для каждой колонки в Row Group будут посчитаны минмальные, максимальные значения и другие статистики
		 4. при запросах с фильтрацией используются статистики, чтобы не читать нерелевантные row groups. Например запрос с `WHERE age > 30` пропустит блоки, где `max(age) <= 30`.
